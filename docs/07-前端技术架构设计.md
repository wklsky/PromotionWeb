## 1. 技术选型

| 模块 | 官网(taiji-web) | CMS(taiji-admin) |
| ---- | --------------- | ---------------- |
| 框架 | Nuxt3 (SSR)     | Vue3 + Vite (CSR) |
| 语言 | TypeScript      | TypeScript       |
| UI   | Tailwind CSS    | Element Plus     |
| 动画 | GSAP            | —                |
| 3D   | Three.js        | —                |
| 状态 | Pinia           | Pinia            |
| 接口 | Axios           | Axios            |
| 构建 | Vite (Nuxt)     | Vite             |

后端：`Spring Boot 3 + MyBatis Plus + MySQL + Redis`；共享：`taiji-shared`。

## 2. 为什么官网用 Nuxt3

企业官网重点在 SEO、首屏速度、SSR、收录。Nuxt3 文件路由 + `useSeoMeta` + 服务端直出 HTML 天然契合。

## 3. 双前端工程与共享层

- `taiji-web`：C 端展示 + 3D，SSR/SEO 诉求强。
- `taiji-admin`：运营后台，纯 CSR。
- `taiji-shared`（monorepo workspace 或私有 npm 包）：统一 **API DTO 类型、枚举常量（新闻分类/招聘状态）、表单校验规则**，杜绝两端契约漂移。

## 4. 官网目录结构

```
taiji-web/
├── assets/          # 全局样式、字体、精灵图
├── components/
│   ├── common/      # Header / Footer / NavDrawer
│   ├── three/       # TaiChiModel.vue（3D太极球，异步加载）
│   ├── sections/    # HeroSection / BrandSection / HallCards
│   └── business/    # 龙虎/熊猫/鲲鹏馆区块组件
├── composables/     # useScrollReveal / useParallax / useCountUp
├── layouts/         # default.vue
├── pages/           # 见 03-IA 路由表
├── stores/          # 轻量全局状态（导航/主题）
├── utils/           # request 封装、SEO 工具
├── api/             # 接口模块（引用 taiji-shared 类型）
└── server/          # 可选 BFF 聚合
```

## 5. 状态管理约定

- 禁止组件内滥用全局状态；跨组件通信走 Pinia 模块或 composables。
- 服务端数据用 `useAsyncData` / `useFetch` 获取（Nuxt 内置，自动去重与 SSR 注水）。

## 6. 接口层封装

- `utils/request.ts`：基于 Axios，统一拦截器（token、错误提示、401 跳转登录）。
- 所有返回值类型来自 `taiji-shared`，严禁 `any`，未知用 `unknown` 收窄。

## 7. 3D 与性能策略

- `TaiChiModel.vue` 用 `defineAsyncComponent` 懒加载，仅在 `≥1024px && prefers-reduced-motion: no-preference` 挂载。
- Three.js 资源走 CDN/预加载，避免阻塞 LCP。

## 8. 响应式与降级

- 见 03-IA 第6章断点；移动端不加载 3D，以静态视觉稿 + CSS 动效替代。
- 使用 CSS 变量切换各馆主题色（见 05-UI 第2.2节）。

## 9. 构建与部署

- 官网：`nuxt build` → 产出 SSR 服务（Docker）。
- CMS：`vite build` → 静态资源（Docker + Nginx）。
- 详见 17-部署方案、18-CICD文档。

## 10. 质量门禁

- TS strict 模式；ESLint + Prettier 强制。
- 组件逻辑 >100 行必须抽 `useXxx.ts`。
- CI 中跑 Vitest + Lighthouse 性能门禁（LCP 不达标阻断）。
